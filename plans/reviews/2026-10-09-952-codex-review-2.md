## (b) New defects introduced or exposed by the fold

### 1. A1’s prefix policy is simultaneously incomplete and overbroad

This is the most important new defect in the amendment.

It is incomplete because composed subscriptions include bare compatibility topics:

- `session.completed` and `session.failed`, not only their `agent/` forms: `main-source/bobi/events/subscriptions.py:88-105`.
- Bare monitor event types such as `support.email`, not only `monitor/support.email`: `main-source/bobi/events/subscriptions.py:108-130`.

The add-then-remove sequence makes those bare keys reachable through A1’s “actual workspace delta” rule.

It is overbroad because `agent/` is a real event namespace, not synonymous with the two lifecycle subscriptions. `agent/auto_dispatch.failed` is published by the framework but is not one of the automatically composed lifecycle keys (`main-source/bobi/events/reactor.py:364-388`). Rejecting the entire prefix breaks a legitimate generic subscription, contradicting D1’s generic-topic surface at `spec.md:34-40` without acknowledging that scope reduction. `monitor/` has the analogous problem for source-qualified monitor events not owned by the current local monitor configuration.

The spec needs an ownership-aware rule: workspace edits cannot remove the derived layer, even when the same string also appears in the workspace layer. Prefix rejection alone cannot represent overlapping ownership.

### 2. A9 is real, but its proposed fix is not complete

The defect is real. `file_lock` uses blocking `LOCK_EX` with no nonblocking flag or deadline (`main-source/bobi/fsutil.py:162-184`). The design holds it across network work (`spec.md:280-282`). Resource authorization can perform one 10-second request per GitHub/Linear topic (`main-source/bobi/events/server.py:650-655`, `:781-784`), followed by a 10-second PUT. A stuck or suspended holder can block another process indefinitely; even normal timeout behavior can delay boot for roughly 70 seconds on the stated six-topic example.

However, A9 does not choose a fix:

- “Non-blocking with a deadline” does not say which of the CLI, boot registration, saved-deployment sync, and reconnect writers time out, nor what each does after timeout.
- “Serialize the apply some other way” merely restates the problem.
- A2 specifically requires the reconnect hook to hold the accepted-record lock across PUT (`spec.md:576`), while A9 leaves open an architecture where that lock is restricted to record RMW (`spec.md:671-672`).

A9’s claim that `spec.md:312` states a universal “never hold a lock across network” rule is slightly overstated: that sentence is specifically about the workspace-file lock. The availability problem with the accepted-record lock nevertheless remains valid.

### 3. The amendment leaves multiple incompatible canonical algorithms in one document

The amendment usually admits that earlier text is wrong, but the current document still gives implementers both versions:

| Body instruction | Later amendment |
|---|---|
| Reuse the existing parser (`spec.md:184-186`, `:353-358`) | Use a separate strict workspace validator (`spec.md:612`) |
| Three apply writers hold the accepted lock across apply (`spec.md:280-282`, `:366`) | Add the reconnect writer, then possibly stop holding that lock across apply (`spec.md:576`, `:671-672`) |
| Missing state files decide persist-only (`spec.md:307-308`, `:316`, `:332-333`) | Manager liveness decides live versus persist-only (`spec.md:600`) |
| PUT then save the record (`spec.md:327`) | Add an unspecified journal or remove the record as a correctness source (`spec.md:586-588`) |
| Helper has no retry (`spec.md:369-373`) | Helper retries once (`spec.md:624`) |
| GET is unnecessary and out of scope (`spec.md:509-521`) | GET may be required to satisfy D4 and recover A3 (`spec.md:676-687`) |

Later text normally takes precedence, but several later entries do not select a replacement. The result is not one executable design.

### 4. A4 needs a state truth table

`team_status().manager_running` answers the liveness question, but it cannot supply deployment identity or an accepted baseline. The amendment says liveness—not file existence—selects live versus persist-only (`spec.md:600`), while the body says a running pre-upgrade manager with no accepted record is persist-only (`spec.md:332-333`).

The spec must define at least:

- manager false, stale records present;
- manager true, deployment and accepted records present;
- manager true, deployment missing;
- manager true, accepted record missing;
- manager changes state during step 3’s potentially slow discovery.

The first two are obvious. The remaining cases are not, and the current body and amendment give different selection rules.

### 5. A9’s new tests are missing

A9 supplies no required test. At minimum the design needs deterministic coverage that:

- a stalled CLI holder cannot block manager boot beyond the chosen deadline;
- reconnect contention does not reassert stale state;
- timeout/failure leaves a state that the next writer can reconcile;
- whichever writer loses reports or retries according to the selected protocol.

### A9 overall

A9 is independently verified as a real major defect. Its diagnosis is substantially correct; its stated repair is not sufficient for implementation because it offers two architectural families and specifies neither.

## (d) Verdict

**REQUEST CHANGES**

This spec is not safe to hand to an implementer.

Must change in the spec:

1. Choose one crash-recovery/read-back architecture for A3 and fully specify its state transitions. If D4 remains literal, introspection must verify current routing/index membership, not merely the deployment’s declared list.
2. Choose one bounded serialization protocol covering boot registration, saved-deployment sync, CLI mutation, and reconnect. Reconcile A2 with A9 and specify timeout behavior and recovery for every writer.
3. Replace A1’s prefix-only rule with ownership-aware handling that protects both forms of derived lifecycle/monitor topics without banning unrelated `agent/` or `monitor/` subscriptions.
4. Decide duplicate and unknown-key policy for the strict workspace schema.
5. State the liveness/identity truth table and rewrite the canonical algorithm, tests, header, and citations so there is one implementation path.
6. Resolve the partial server-replace failure semantics: transaction, rollback/reconciliation, or an explicit accepted-risk decision with recovery behavior.

Real human/product decision:

- Q3 is a genuine product decision only if Zach is willing to revise D4 from “what the server actually routes” to “what the server last accepted.” If D4 remains unchanged, live introspection is not optional.
- Q4 is primarily an engineering correctness decision, not product scope. A human can explicitly accept the known failure mode and defer transactional repair, but the spec must record that acceptance and define how operators recover.

The spec is converging in the narrow sense that A2, A4, A6, and A7 close real findings. Architecturally, however, it is still thrashing: the same class of defect—another writer, another stale cache boundary, another non-atomic transition—keeps reappearing.

What is structurally missing is a single distributed-state protocol: named sources of truth, invariants, a transition/state table, ownership of derived versus declared topics, all writers, serialization rules, crash points, and reconciliation behavior. Without that model, each review patches the newly noticed race while exposing the next one.
