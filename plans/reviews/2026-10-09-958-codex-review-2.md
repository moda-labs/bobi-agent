## (b) New defects introduced by section 9

### N1 - BLOCKER - `chown -h` does not neutralize an `auth.json` symlink

- **Section 9 says:** A3 permits “`[ -L ]` test and refuse, or `chown -h`” before a root write.
- **Evidence:** `chown -h` acts on the link itself. The subsequent `Path.write_text` at `docker/docker-entrypoint.sh:329-330` follows the link and writes the protected target.
- **Impact:** A builder may implement an option the spec explicitly calls safe while retaining the ownership/content attack F3 identified.
- **Required fix:** Mandate one behavior: use `lstat` semantics and fail before any ownership change or write when `auth.json` is a symlink or unexpected type. Remove `chown -h` as a standalone alternative. Also decide whether a bad `/data/codex` path is repaired or causes boot failure; the mechanism and test must agree.

### N2 - MAJOR - A2 has no complete non-blocking lock protocol

- **Section 9 says:** Use a unique deployment name and “take a non-blocking per-target lock before posting.”
- **Evidence:** The repository’s shared `file_lock` is blocking-only at `bobi/fsutil.py:162-184`; the earlier Q3 text explicitly rejected changing it and suggested a pidfile instead. Section 9 reverses the decision without selecting a mechanism. It also does not say that the key is the resolved login spec, so `target=None` on a codex brain and `target="codex"` can be implemented as different locks.
- **Impact:** The original concurrent-writer/listener blocker can survive a nominal implementation of A2.
- **Required fix:** Specify a machine-wide lock keyed by resolved `spec.kind` or credential path, acquired before listener registration/posting and held through credential verification and outcome posting. Define non-blocking acquisition. The two-process test must assert exactly one ask, one CLI spawn, a deterministic loser result, and successful completion by the winner.

### N3 - MAJOR - “Known brain kinds” is broader than supported login specs

- **Section 9 says:** Validate `target` “against the known brain kinds.”
- **Evidence:** `known_brain_kinds()` includes `stub` (`bobi/brain/__init__.py:54-58`, `:490-494`), while `_SPECS` contains only Claude and Codex and `_active_spec()` falls back to Claude for anything else (`bobi/auth_bootstrap.py:92-120`).
- **Impact:** `login-bootstrap stub` can pass the stated validation and silently select the Claude login flow. A generic “invalid target” test will miss this because `stub` is known.
- **Required fix:** Validate against supported login targets, not registered brains. Prefer an explicit CLI choice—initially `codex`, plus `claude` only if intentionally supported—and add `stub` and gateway aliases to rejection tests.

### N4 - MAJOR - Mandatory quarantine contradicts Q8’s conservative option

- **Section 9 says:** Q8 Option B keeps the sweep conservative and handles malformed credentials only through Q7; A8 simultaneously mandates quarantine “independent of that answer.”
- **Evidence:** An unrecognized file may be a valid newer Codex schema—the exact uncertainty motivating Q8. Renaming it removes it from the path Codex reads, causing the same authentication outage as deletion even though recovery remains possible.
- **Impact:** Option B cannot be implemented as written, and a future-valid credential can still be disabled automatically at boot.
- **Required fix:** Choose the conservative rule now: leave unknown schemas untouched during boot. If explicit human-gated rebind is selected, quarantine only during that rebind, with a collision-free, no-overwrite name and a documented restoration path.

### N5 - MAJOR - A9’s phase model is incomplete

- **Section 9 says:** Give “the ask wait, the URL scrape, the device authorization and the post-code exit separate budgets.”
- **Evidence:** Claude ask-first has a second human wait after the URL is posted: waiting for the pasted code. That phase is absent from the list. Current public configuration has only `--timeout` plus internal `url_timeout`.
- **Impact:** Implementers can still share a deadline across the ready reply and pasted-code wait, or silently change `--timeout` semantics. The original “human consumed the device lifetime” class is not fully excluded.
- **Required fix:** Define phase-by-phase budgets and their public configuration:

  - ready-reply wait;
  - URL/code scrape;
  - Claude pasted-code wait or Codex device authorization;
  - post-code/process exit.

  State which existing option controls each, whether a value is reused as a fresh budget, and the exact late-reply behavior.
