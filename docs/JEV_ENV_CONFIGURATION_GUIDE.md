# Guide: Configuring TypeSafe JEV Dynamic Routing via `.env`

TypeSafe JEV Dynamic Model Routing in Bobi allows your agent fleet to dynamically assess task complexity and route execution to the most capable, cost-effective model (e.g., routing lightweight edits to `ds/deepseek-flash` and complex multi-file architectural reasoning to `ds/deepseek-v4-pro` or `claude-3-5-sonnet`).

Because real-world routing relies on **model-specific trust instructions**, **domain-specific complexity criteria**, and **custom task allowlists**, JEV is designed to be configured manually and precisely via the agent's environment file (`run/.env`).

The Web UI provides a **minimal toggle** (Enable/Disable) and live status inspector, while the full policy specification lives directly in your configuration file.

---

## 1. File Location & Environment Variables

All configuration lives in the agent's runtime environment file:
```text
~/.bobi/agents/<agent-name>/run/.env
```
*(Or your team's local deployment `run/.env` file).*

### Required Environment Variables

| Variable | Description | Example / Format |
| :--- | :--- | :--- |
| `BOBI_METRICS_EXPERIMENT_JSON` | The single-line JSON string containing the complete JEV routing policy, candidate models, instructions, and scope. | `{"experiment_id": "...", "policy": {...}}` |
| `BOBI_METRICS_ASSIGNMENT_SECRET` | 32-byte secret used for privacy-safe HMAC variant assignment. Auto-generated by Bobi if omitted. | `dqcHU-jsY1_rwLr2SkxPSR-UyS8V_SUdFJMTPCY0sqs` |
| `TYPESAFE_API_KEY` | Your vendor API key for the TypeSafe AI routing endpoint (`https://api.typesafe.ai/v1/systemone`). | `apikey_...` |

> [!NOTE]
> To temporarily **disable** JEV without deleting your configuration, comment out the line in `.env`:
> ```bash
> # BOBI_METRICS_EXPERIMENT_JSON={"experiment_id": ...}
> ```
> Toggling the switch in the Web UI performs this exact commenting / uncommenting automatically.

## 2. Policy Schema: `BOBI_METRICS_EXPERIMENT_JSON`

The JSON structure contains top-level experiment metadata and an inner `policy` object:

```json
{
  "experiment_id": "eng-team-jev-enforce-v1",
  "router_name": "bobi-arm",
  "router_version": "1",
  "policy_version": "eng-team-policy-v1",
  "feature_schema_version": "jev-features-v1",
  "control_model": "ds/deepseek-flash",
  "cohort": "eng-team-production",
  "variants": [
    {
      "variant_id": "control",
      "weight": 0.0,
      "model": "ds/deepseek-flash"
    },
    {
      "variant_id": "treatment_jev",
      "weight": 1.0,
      "policy": "typesafe-jev"
    }
  ],
  "policy": {
    "name": "typesafe-jev",
    "version": "jev-1.13.0",
    "brain": "claude",
    "mode": "enforce",
    "candidate_models": [
      "ds/deepseek-flash",
      "ds/deepseek-v4-pro"
    ],
    "scope": {
      "roles": [
        "director",
        "engineer"
      ],
      "entry_points": [
        "subagent_persistent",
        "subagent_phase",
        "workflow_start"
      ]
    },
    "egress": {
      "prompt": "none",
      "max_prompt_bytes": 8192
    },
    "credential_env": "TYPESAFE_API_KEY",
    "options": {
      "instructions": "Route according to task reasoning demands and complexity. Always select the least costly model capable of solving the task accurately.",
      "criteria": {
        "ds/deepseek-flash": "Use for routine file lookup, single-file edits, linting, simple function refactors, unit tests, and mechanical boilerplate tasks.",
        "ds/deepseek-v4-pro": "Use for complex architectural refactors, subtle bug hunts, multi-step planning, concurrency issues, and mission-critical code changes."
      }
    },
    "min_confidence": 0.85,
    "deadline_ms": 3000,
    "max_in_flight": 8,
    "store_reason_text": false
  }
}
```

---

## 3. Key Fields Explained

### A. Routing Mode (`mode` & `variants`)
* **Enforce Mode (`"mode": "enforce"`)**:
  * JEV actively picks the best candidate model and executes it for the session.
  * In `variants`, set `control` weight to `0.0` and `treatment_jev` weight to `1.0`.
* **Shadow Mode (`"mode": "shadow"`)**:
  * JEV evaluates the task in background and records policy recommendations to telemetry without altering execution (always runs `control_model`).
  * In `variants`, set `control` weight to `1.0` and `treatment_jev` weight to `0.0`.

### B. Scoped Roles (`scope.roles`)
* Only sessions whose `role` matches one of the entries in `scope.roles` are evaluated by JEV.
* **`director`**: The manager/planning session that chats with users and coordinates tasks. Include `director` if you want user conversations and planning routed dynamically.
* **`engineer`**: Coding subagent sessions spawned for issue and PR workflows. Include `engineer` to optimize coding token expenditure.
* Sessions with roles not in this allowlist immediately bypass JEV and run the default model.

### C. Model-Specific Trust Criteria (`options.criteria`)
* Every model in `candidate_models` **must have a corresponding entry** in `options.criteria`.
* Write clear, objective guidance describing the capabilities and complexity boundaries of each model.
* Example:
  ```json
  "criteria": {
    "ds/deepseek-flash": "Use for standard code edits, unit test fixes, mechanical refactoring, and single-file modifications.",
    "ds/deepseek-v4-pro": "Use for high-complexity tasks: complex debugging, multi-module architectural changes, and security-critical code."
  }
  ```

### D. Safety & Fallback Controls
* **`control_model`**: The fallback model (e.g., `ds/deepseek-flash`). If the TypeSafe API times out, returns an error (such as HTTP 401 or 500), or confidence is lower than `min_confidence`, Bobi instantly falls back to `control_model` with zero downtime.
* **`min_confidence`**: Minimum threshold (e.g. `0.85`). If JEV's confidence is below this value, the fallback model executes.
* **`deadline_ms`**: Monotonic timeout (e.g. `3000` ms). If routing takes longer, the session launches immediately with the control model.

---

## 4. Applying Changes: Restarting the Agent

> [!IMPORTANT]
> **Why restart is required for active sessions:**
> In Bobi, model assignment is decided **once per fresh brain session** upon launch. The long-running `director` session maintains its bound model for its entire lifecycle.
>
> When you update `.env`:
> 1. In the Web UI: Click **Save & Restart Agent** in the JEV modal.
> 2. Via CLI: Run `bobi agent restart <agent-name>`.
>
> Once restarted, the `director` and all subsequent workflow workers (`engineer`) immediately adopt the updated JEV policy.
